# DECISIONS.md — rulings made while building the project

Format: **Ruling** — why — cost if wrong.

1. **Project root = this folder (`sms_spam_detection_filter/`) instead of a new `sms-spam-ml/` subfolder.** — HANDOFF.md lives here and the tree in §4 starts with HANDOFF.md at the root, so the folder *is* the project root. — Cosmetic only; rename the folder if the name matters.
2. **Python 3.12 in a local `.venv`.** — The system `python3` is 3.9 (spec needs 3.10+); 3.12 was available. — None.
3. **Report built with python-docx (as HANDOFF §11 says), not docx-js.** — The spec names `report/build_report.py` with python-docx. — None.
4. **Self-checks for `clean_text` live in `src/preprocess.py` (`python -m src.preprocess`), no separate `tests/` folder.** — §4 says "create exactly"; §12 asks only for unit checks that print 5 cleaned examples. — None.
5. **Duplicates are detected after HTML unescaping and whitespace stripping.** — Two messages that differ only by `&lt;` vs `<` or trailing spaces are the same message. — Count of duplicates could differ by a handful from a raw-text dedupe.
6. **Table 4.1 "Validation" row reports the per-fold size (825–826) rather than a separate split.** — Validation is 5-fold CV inside the training set (spec §5.4); listing it as 80 % would double-count. — None.
7. **LinearSVC uses `dual="auto"` and `max_iter=10000`.** — `dual="auto"` per spec note for sklearn ≥ 1.3; higher max_iter avoids convergence warnings at C = 10. — None.
8. **Workflow figure (Fig. 5.1) places the train/test split before feature extraction**, and groups text preprocessing + BoW/TF-IDF + classifier inside one "scikit-learn Pipeline (fitted on training data only)" box. — The spec's linear order (Feature Engineering → Split) would visually contradict the no-leakage design that the report claims. All stages named in the spec are kept. — None.
9. **Colours:** ham `#2a78d6` (blue), spam `#eb6834` (orange); classifiers NB `#1baf7a`, LR `#6250d6`, SVM `#eda100`; BoW drawn dashed / hatched, TF-IDF solid. — Palette checked with a colour-vision-deficiency validator (all pairs distinguishable); vectorizer has a secondary encoding so colour is never the only cue. — None.
10. **Two messages become empty after cleaning (pure emoticons ":)", ":-) :-)").** They are kept (a zero vector is classified by the prior/intercept). — Removing real data would be an undocumented filter. — Negligible.
11. **Literature:** all 12 sources were verified (see `report/literature_verification.md`). Two were corrected: ref. Gómez Hidalgo 2006 uses full Spanish double surnames; Sahami 1998 gets pages 55–62 and AAAI Tech. Rep. WS-98-05. Porter (1980) is added because the ablation uses the Porter stemmer. — Citation accuracy. — None.
12. **Extra helper files in `report/`:** `docx_helpers.py` (formatting helpers) and `lo_export.py` (LibreOffice export). — Keeps `build_report.py` readable. — None.
13. **List of Figures / List of Tables use `TOC \t "Figure Caption,2"` / `"Table Caption,2"` (caption paragraph styles) instead of SEQ fields.** — HANDOFF §11.2 allows "what works reliably". This lists the exact caption text ("Fig. 3.1: …", "Table 3.1: …") with page numbers in both Word and LibreOffice; verified in the PDF. — If the department insists on SEQ fields, captions would need re-building.
14. **PDF export uses a LibreOffice Basic macro in a throw-away profile.** — The LibreOffice-bundled Python is blocked by macOS quarantine; changing quarantine flags on a system app was not done. The macro updates all indexes three times, then exports. — None.
15. **Figs. 6.4, 6.5, 6.6, B.1 are dot / dumbbell plots instead of bar charts.** — All scores are 0.92–0.99; bars starting at zero hide the differences and truncated bars mislead. The axis label states that it does not start at 0. — Cosmetic; switch back to bars in `evaluate.py` if bars are required.
16. **Page budget (25–35 pages, Ch. 1–7):** figures were reduced to ≤ 5.5 in (HANDOFF §11.5), Figs. 3.5 and 3.6 are placed side by side (each keeps its own number and caption), and repetitive sentences were cut. Font size, margins and line spacing were not changed. Main body = 35 pages in the LibreOffice PDF. — Word may paginate slightly differently.
17. **Certificate and Declaration wording:** the department template text was not available, so standard wording was used with the title, names and placeholders filled. — Replace with the department's exact wording if it differs.
18. **The notebook re-runs the whole pipeline**; `run_all.py` executes it after the scripts, so the report's timing values come from the notebook run. All other results are deterministic and identical. — None.
19. **Best model chosen by test F1 (HANDOFF §8.1).** The report states that this makes the winner's score slightly optimistic and reports CV results alongside. — None.
20. **Dataset facts from the UCI page** (DOI, licence, per-source counts) are stored in `src/config.py` → `outputs/results/dataset_info.json`, so the report still reads every number from `outputs/`; EDA checks that the per-source counts add up to the class counts of the downloaded file. — None.
21. **Linear SVM loss:** HANDOFF §10 says "hinge loss"; scikit-learn's `LinearSVC` uses the squared hinge by default. The report states the loss actually used. — None.
22. **Fig. 6.7 shows both LR coefficients and NB log-probability ratios** (HANDOFF allows "and/or"). The best LR model (BoW, C = 100) puts large weights on some rare campaign-specific words; the NB panel gives the more readable view. — None.
23. **scikit-learn's stop-word list contains "call", "now", "get", "please"**, which are frequent in spam. The list was kept as specified; the ablation (Appendix B) shows that removing stop-word filtering lowers F1, so the choice is supported by data. — None.
